## 상세

### ISSUE-001 — 설비 조회에 정렬이 없었다 (High)

`findBySiteId`에 `ORDER BY`가 없었다. 실측에서 id 순도 이름 순도 아닌 순서로 돌아왔다
(`2,1,5,3,4,6`). Postgres는 순서를 보장하지 않는다.

두 곳에서 문제가 된다. 화면의 기본 선택이 목록 첫 행이라 **무대에서 드롭다운이 다른
설비를 물고 시작**하고, 더 심각하게는 **설비 매칭의 후보 풀 순서가 흔들린다** — 유사도
동점일 때 같은 입력에 다른 설비가 붙으면 설비 이력이 두 ID로 쪼개진다.

조회에 `ORDER BY id`를 걸고 후보 정렬의 2차 키로 설비 id를 넣었다.

### ISSUE-002 — 새로고침 시 대화 맥락 소실 (High)

재현: UC3 대화 중 F5.

직전 턴에서 `findLocationEquipment`가 '공장동 후면 차양부 / 이동식 사다리 A'를 찾아놓고도
새로고침 후 **"정확한 작업 장소가 어디인지 알려주시겠습니까?"** 로 되돌아갔다.

대화 ID를 `sessionStorage`에 남기고 `GET /api/agent/{id}/transcript`로 기록을 복원한다.
트레이스는 복원하지 않는다 — 도구 호출은 그 턴의 사건이고, 지난 턴의 트레이스를 다시
그리면 방금 일어난 일처럼 보인다.

**수정 후 실측**: 새로고침 뒤 다음 턴에서 장소를 다시 묻지 않고 바로 5개 도구를 실행해
작업계획서를 완성했다.

### ISSUE-004 — 타임라인 인과 순서 (Medium)

같은 날짜(2026-09-21)의 세 사건이 `작업계획서 → 사고 → 수시평가`가 아니라
`수시평가 → 작업계획서 → 사고` 순으로 그려졌다.

같은 날짜 안의 인과 순서를 백엔드가 매긴다:
평가(0) → 조치(1) → 작업계획서(2) → 사고(3) → **그 사고가 만든** 수시평가(4).

### ISSUE-006 — 오탐

`findLocationEquipment`가 한 턴에 세 번 호출되는 것을 보고 중복/매칭 실패를 의심했다.
`tool_call.params_json`을 열어보니 인자가 매번 달랐다:

```
"공장동 후면 차양부 이동식 사다리" → "공장동 후면 차양부" → "이동식 사다리"
```

모델이 스스로 질의를 좁혀간 것이다. 매처가 첫 질의를 한 번에 푸는지 테스트로 박았고
(7건 통과) 매처 탓이 아님을 확인했다. **수정하지 않는다.**

### ISSUE-012 — 전역 예외 처리기 부재 (High)

없는 자원 7개 경로 + 상태 전이 위반 + 잘못된 입력 = 12건이 전부 500이었다.

상태코드는 **예외 타입으로** 고른다. 메시지에 "찾을 수 없습니다"가 들어갔는지 검사하는
방식은 문구를 다듬는 순간 404가 400으로 조용히 바뀐다.

`/form/**`은 사람이 브라우저로 여는 화면이라 JSON 대신 읽을 수 있는 HTML을 돌려준다.

### ISSUE-016 — 키 없이 UC3가 죽었다 (Critical)

2차 라운드에서 나왔다. 1차는 라이브 키로만 쳤기 때문에 못 봤다.

`DemoModeConfig`가 데모 모드를 감지해 "데모 모드입니다" 안내 토큰을 찍으면서도,
그 직후 **자리표시자 키로 모델을 호출**했다. 결과는 `Failed to generate content`와
도구 0/6 발화.

`DemoConversationScript`를 만들어 모델 없이 UC3를 끝까지 돌게 했다.
**대체되는 것은 문장 생성뿐이다** — 도구는 실제로 실행되고 데이터는 시드 DB에서
진짜로 나온다. 화면에 데모 모드임을 명시한다.

실측(키 없이): 도구 9회 전부 성공, 6/6종, 제품명 '○○ 유성페인트' 추출,
화재 '중'(유기용제 추론), 톨루엔 MSDS TWA 50ppm·H225. 라이브와 같은 브리핑이 나온다.

### ISSUE-017 — 슬롯 갱신이 500 (High)

`@PrePersist`는 INSERT에서만 돈다. 기존 슬롯을 UPDATE할 때 `answered_at`을 비워
NOT NULL 위반이 났다.

**라이브에서도 터지는 경로다.** `extractWorkPlan`의 도구 설명이 "이전에 채운 값은
그대로 다시 넣으세요"라고 지시하므로 갱신은 예외가 아니라 정상 흐름이다.
데모 모드가 매 턴 값을 다시 보내면서 드러났을 뿐이다.

### ISSUE-018 — README가 심사위원 경로를 안내하지 않았다 (High)

"5분 안에 띄우기"가 **개발자 경로**(Java 21 + Node 직접 설치, 터미널 2개)였다.
심사위원이 이걸 따라하면 5분에 못 끝낸다. 제출 경로(`docker compose up -d --build`,
키 불필요)를 맨 위로 올리고 실측값을 적었다.

## 남은 것 (수정하지 않음)

- **인증이 없다.** `SecurityConfig`가 `/api/**`를 permitAll로 연다. 가상 사업장 1곳에
  역할 2종이라 이번 범위에서 로그인 UI를 만들지 않기로 한 결정이고,
  `.claude/rules/deployment.md`에 "공개 네트워크에 띄우지 않는다"로 적혀 있다.
  **심사 제출 전에 이 줄을 다시 읽을 것.**
- **`/api/admin/public-api/crawl`이 열려 있다.** 운영자 도구인데 보호가 없다.
  무대에서 부를 일이 없고 키가 없으면 안내 문구만 돌려주지만, 위 인증 결정과 함께 본다.
- **UC1 협착(CAUGHT) 축**은 정지 사진에서 0건이다 (사전 판독 8장, 2026-09-20).
  9/23 정식 게이트에서 별도로 판정한다.

## 시연 관점 메모

- 프로젝터 1280×720에서 타임라인은 **요약 카드 + 사건 3건**까지 보인다.
  사고는 스크롤해야 나온다. 요약 한 줄이 논지를 담고 있어 치명적이지 않지만,
  리허설에서 스크롤 시점을 정해둘 것.
- 사고 등록 화면은 소환 결과가 화면 상단 빨간 박스로 먼저 뜬다. 등록 완료 메시지가
  아니라 **"이 사고는 예고되어 있었습니다"** 가 먼저 읽힌다.
- 후보 채택률은 시드 상태에서 **80% (4/5)** 다. 100%가 아닌 것이 중요하다.
