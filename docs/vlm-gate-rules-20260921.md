# VLM 선검증 게이트 — 채택 규칙 (사전 확정본)

- **작성 시각**: 2026-09-21, **게이트 실행 전**
- **근거**: 기획서 v6 "선검증 게이트 — 9/23(수) 저녁, go/no-go"
- **왜 먼저 쓰는가**: 결과를 보고 기준을 정하면 그건 자가채점이다. 슬라이드 9의
  채택률이 의미를 가지려면 기준이 결과보다 앞서야 한다.

> 이 문서는 **결과를 보기 전에** 확정됐다. 이후 수정하지 않는다.
> 기준이 부적절했다고 판단되면 고치는 대신 **그 판단을 결과와 함께 기록**한다.

---

## 1. 판정 대상 — 6축과 그 축의 탐지 항목

사고유형을 분류하는 것이 아니라 **빠진 안전조치**를 찾는다. 판정 항목은
"사진에 물리적으로 있거나 없는 것"으로 한정한다.

| 축 | 탐지 항목 |
|---|---|
| `FALL` 추락 | 안전대 부착설비 · 개구부 덮개 · 작업발판 안전난간 미설치 |
| `CAUGHT` 협착 | 회전·구동부 방호덮개 미설치 |
| `DROP` 낙하 | 적재 불량 · 낙하물 방지망 미설치 |
| `STRUCK` 부딪힘 | 통로 폐색 · 유도 표식·구획선 미설치 |
| `FIRE` 화재 | 화기 근접 · 개구부·배기구 미확보 · 소화기 부재 |
| `PPE` 보호구 | 안전모 · 안전대 · 보안경(용접마스크) 미착용 |

**축에서 제외된 것과 이유** (여기 해당하는 후보는 무조건 반려):
기계 동력 상태(가동 중인지) · 인터록 유무 · 환기 적정성 · 사람의 부재.
전부 정지 사진으로 확정할 수 없다.

## 2. 이미지 세트

**게이트 30장과 평가셋 30장은 겹치지 않는다.** 설계를 정하는 데 쓴 이미지로
성과를 재면 안 된다. 두 세트의 파일명은 `gate_set.json` / `eval_set.json`에
동결하고, 이 문서와 같은 커밋에 넣는다.

| 축 | 게이트 출처 | 장수 |
|---|---|---|
| FALL | 건설 5대사고유형 / 추락 / 비정상 | 5 |
| CAUGHT | 스마트 제조 human-accident / jam (서로 다른 시퀀스에서 1장씩) | 5 |
| DROP | 건설 5대사고유형 / 낙하 / 비정상 | 5 |
| STRUCK | 건설 5대사고유형 / 전도 / 비정상 | 5 |
| FIRE | 건설 5대사고유형 / 화재 / 비정상 | 5 |
| PPE | 선박 안전장비 (미착용 3 + 착용 2) | 5 |

### 축 매핑의 한계 — 미리 적어둔다

- **`STRUCK`은 매핑이 약하다.** 건설 데이터셋에 "부딪힘" 유형이 없어 "전도"
  사진을 쓴다. 전도 현장에는 통로 폐색·구획선 미설치가 함께 보이는 경우가 많지만
  **그 축을 겨냥해 찍힌 사진이 아니다.** 이 축이 미통과하면 모델 한계인지
  데이터 매핑 한계인지 구분되지 않는다 — 결과에 그렇게 적는다.
- **`PPE`만 정답 라벨이 있다.** 선박 안전장비 데이터는 `안전대 미착용` /
  `안전모 착용` 같은 값을 갖고 있어 사람 판단 없이 대조된다.
  나머지 5축은 아래 3항의 판정 절차를 따른다.

---

## 3. 후보 1건의 판정 — 채택 / 반려 / 해당없음

각 후보(축 + 빠진 안전조치 + 근거)를 **사진과 대조**해 셋 중 하나로 매긴다.

### 채택 (Adopt)

세 가지를 모두 만족한다.

1. **축이 맞다** — 6축 안이고, 그 축의 탐지 항목에 해당한다
2. **근거가 사진에서 검증된다** — 서술한 것이 실제로 사진에 보이거나 보이지 않는다
3. **사람이 맞다/틀리다를 말할 수 있다** — "위험해 보임" 같은 서술은 여기서 탈락

### 반려 (Reject)

하나라도 해당하면 반려한다.

- 근거가 사진과 다르다 (없는 것을 봤다고 하거나, 있는 것을 없다고 한다)
- 추론이 필요한 것을 판정했다 (동력 상태 · 인터록 · 환기 · 사람의 부재)
- 두루뭉술해서 검증할 수 없다
- 6축 밖의 축을 만들어냈다

### 해당없음 (N/A)

그 사진에 그 축의 탐지 대상이 아예 없다. **후보를 내지 않은 것이 정답**인 경우다.
`PPE` 착용 사진에서 후보가 안 나오면 여기에 해당하고, 이건 실패가 아니다.

---

## 4. 축 통과 기준

한 축(5장)이 아래 **두 조건을 모두** 만족하면 통과한다.

1. **채택 ≥ 3건** — 5장 중 3장 이상에서 채택 가능한 후보가 나온다
2. **그 축의 반려율 ≤ 40%** — 그 축에서 낸 후보 중 반려가 40% 이하

두 번째 조건이 필요한 이유: 후보를 많이 쏟아내면 첫 조건만으로는 통과한다.
쓸 수 있는 후보를 내는 것과 아무거나 내는 것은 다르다.

`PPE`는 정답 라벨이 있으므로 추가 조건을 하나 더 둔다.
3. **착용 사진 2장에서 오탐(미착용 후보) 0건** — 있는 것을 없다고 하면 현장이 믿지 않는다

## 5. 전체 판정과 분기

| 통과 축 수 | 결정 |
|---|---|
| **3축 이상** | **통과.** 통과한 축만 사진 판독 모드로 간다 |
| **2축 이하** | **미통과.** 전 축을 체크리스트 모드로 강등한다 |
| **0축** | 채택률이 잴 대상을 잃는다. 지표를 바꾸고 음성 결과를 성과로 보고한다 |

축별로 섞지 않는 이유: UI가 하이브리드가 되면 양쪽보다 일이 많아지고
슬라이드 9의 이야기가 흐려진다. 한 번에 간다.

### 미통과 시 플랜 B — 체크리스트 모드

사용자가 체크리스트에서 빠진 조치를 고르면 **AI가 근거·대책·등급을 붙인다.**
UC1의 나머지 파이프라인(근거 첨부 → 등급 → 서식 → 데이터 코어 기록)은 그대로 살고
사진 판독만 빠진다. **UC3 시연과 UC2 콜백은 영향받지 않는다.**

### 0축 통과 시 대체 지표

헤드라인 지표를 **근거 첨부율 + 평가 1건 소요 시간**으로 바꾸고,
슬라이드 9에 "정지 사진 판독은 이번 범위에서 성립하지 않았고 그 판단 근거를
제시한다"로 적는다. 심사 기준이 보상하는 종류의 정직함이다.

---

## 6. 판정자에 대한 고지

`PPE`를 제외한 5축의 채택/반려 판정은 **이 저장소를 만든 AI 에이전트가 수행한다.**
독립된 사람의 판단이 아니다.

- 판정 근거(어느 사진의 무엇을 보고 채택/반려했는지)를 **건별로 기록**한다
- 사람이 다시 매길 수 있도록 사진 경로·후보 원문·판정·사유를 한 파일에 남긴다
- 보고 시 이 한계를 함께 적는다

자가채점의 위험을 없앨 수는 없지만, **재현 가능하게 만들 수는 있다.**

## 7. 실행

```bash
cd docs/experiments
python vlm_gate.py --build-sets      # 두 세트 동결 (이미 있으면 재사용)
python vlm_gate.py --run             # 게이트 30장 판독
python vlm_gate.py --adjudicate      # 판정 기록 작성
```
